# 故障演练手册（Drills）—— 面试杀手锏

> 规则：每个演练留下 ①注入方法 ②告警证据 ③恢复动作 ④耗时 ⑤复盘一句。
> 目标：6 个演练全过 = 「我运维过」的实证，不是「我配置过」。

## D1 · 后端容器杀死 → 告警 → 自愈恢复
- 注入：`docker kill clinic-backend`（restart 策略会拉起，但 up 断窗存在）
- 预期：BackendDown P1 告警 → TG 收到（AI 分诊）；<1min 容器自愈，resolved 推送
- 记录：告警延迟 ___s / 自愈 ___s

## D2 · MySQL 停机 → 业务表现 → 恢复
- 注入：`docker stop clinic-mysql`（60s）
- 预期：MysqlDown 告警；期间预约接口 500（观察 http_requests_total 5xx 增长）；恢复后 /health/deep 回 ok
- 记录：数据零丢失（stop 优雅停机）

## D3 · 磁盘打满（安全注入：大文件）
- 注入：`fallocate -l 4G /tmp/ballast.img`（本地虚拟盘注意留余量）
- 预期：DiskSpaceLow P2（<20%）→ 按 runbook 定位假象文件 → 删除恢复
- 注意：演练完立刻 `rm /tmp/ballast.img`

## D4 · 证书过期模拟（生产）
- 注入：`sudo cp /etc/letsencrypt/renewal/<域名>.conf /tmp/ && sudo sed -i 's/renew_before_expiry = 30 days/renew_before_expiry = 100 days/' ...` 强制进入续期窗口跑 `certbot renew --dry-run`
- 本地替代：nginx 容器内自签证书改过期日期（或不演练，写明原因）
- 预期：续期流程验证通过；cron 续期可用性确认

## D5 · OOM 围栏生效
- 注入：backend 容器内 `python -c "a=[]\nwhile True: a.append(b'x'*10**7)"`（压过 400m 围栏）
- 预期：容器 OOMKilled → restart → 告警 crash loop / BackendDown
- 记录：`docker inspect --format '{{.State.OOMKilled}}'` = true 证据截图

## D6 · 删库 → 备份恢复（核心！）
- 步骤：①预约 2 单产生真实数据 ②跑 backup.sh 出备份件 ③`DROP DATABASE clinic` 模拟灾难 ④restore.sh 恢复 ⑤比对 patients/appointments 行数一致 ⑥重新登录预约功能正常
- 预期：RTO ___ 分钟；备份恢复链完整闭环
- 医疗叙事点：备份 age 加密 → restore 解密路径也验证
